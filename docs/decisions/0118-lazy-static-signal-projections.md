# ADR0118: lazily project static non-query signals like original NgRx

Status: candidate16ai, regression first, device benefit pending.

Installed originalNgRx Store.selectSignal returns computed(()=>selector(this.state()),options). SQLite currently computes each signal's selector eagerly inside cache generation publication, before observable emission. FlatPage has count/target/derived signals; count enumerates5000keys. Benchmark emission therefore includes work that originalNgRx may defer until the signal is read.16ah/16ah2 measure publication inclusive callbacks, not exactCPU or proof of individualselector mapping.

For static selectors with no query sources only, retain the existing scoped input watcher, loading/defaults/leases and readiness; publish its scoped view to the internal signal. Invoke the real selector in returned computed on demand. Keep dynamic discovery and all query-source signals on the existing path. No queue bypass, notification-before-commit, schema/SQL/cache or Store API change.

Preserve reactive error recovery: computed always reads its input before throwing; track a failed lazy projection and let a later cache generation retry even when scoped inputs retain identity. Internal signal equality suppresses identical healthy views, but invalidates a failed projection on retry. Returned computed still uses caller equality. Existing unrelated equality-call regression must stay green.

Required regression: no projector invocation on construction or dispatch until read; values then current. Error recovery on a later unrelated generation with identical scoped input must still work. Full existing dynamic/query/default/identity/error tests and all library checks, mandatory50kguard/reversedAPKs/fullfreshmatchedshapes+list acceptance before retention. No benefit claim or floor change from shifting lazy timing alone; DOM metrics and all mean guards remain required.
