# Bridge cost: phase 13

Node v26.5.1; sql.js 1.15.1; SQLite 3.54.0; win32/x64; AMD Ryzen 5 3600 6-Core Processor              ; 31.9 GiB RAM. Production mode (no dev freezing). In-memory WASM; no disk or Capacitor bridge.


After counts are driver invocations per complete dispatchAsync action (batch = one), including transaction boundaries and subscribed refresh. Historical before counts are phase 11 individual SQL statements, including sql.js internal queries; they are retained as a complexity baseline. Cold starts without subscriptions; active pins the entire store before measuring. State assertions/materialize and reseeding happen outside measured actions (identical before/after workload). Both modes use 500 entities and three scalar extras, plus a 300-element pointer array. Shared workload: spikes/bridge-cost-workload.ts; enforced by src/lib/entity/bridge-cost.spec.ts.

The brief's original two-extra-property workload measured reset at 1016; the extended three-property workload below resets exactly 500 rows after add/remove and measured 1014. Before counts were captured from the extended failing acceptance tests before implementation; after counts are regenerated by npm run spikes. Phase 13 floor acceptance (same method-invocation counter before/after): fresh ui scalar 5 -> 1; cold toggle plus count 6 -> 3; cached collection toggle 4 -> 1 (2 with count); page-cached toggle 2 calls. A 50k setAll has no collection read-back and uses one batch for its 252 INSERT statements; the complete cold-clear path includes transaction controls and prerequisite reads. Native and web evidence is recorded in docs/benchmarks/phase13-bridge-and-retention.md.
