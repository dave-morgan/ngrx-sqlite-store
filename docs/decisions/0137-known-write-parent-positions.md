# ADR0137: repair positions from complete known writes

Status: Rejected16bk SQL-reload repair; correctness regression remains open.

ADR0136's full object-shell candidate is rejected and all four production files restored byte-exact. Its borrowed-root shortcut and broad metadata helper are absent. Its TDD separately reproduced a real existing bug: after an active cache owner is updated by splicing a known written leaf, the owner can keep outdated childPos metadata. A subsequent insertion can reuse a physical position or change ordering. The inactive complete-owner adoption case already passes baseline and is not claimed broken.

Isolate three generic regression cases from the fifteen archived16bi tests: active/inactive addition with a subsequent ordered write and prior-metadata isolation; same-key delete/re-add with authoritative persisted positions. The other twelve shortcut-specific/fallback tests remain archived with the rejected feature. Five further cases cover nested metadata, same-count ancestor replacement, prepended input keys, exact-object input reordering and read-free scalar splicing. Do not claim the baseline correct or remove its real regression to make checks green.

The initial24-line target-widening repair reached449 passing library tests but independent review found a real ordering regression: `{added:7,...form}` produced cached `added,name,details` while SQLite retained `name,details,added`. A new test reproduced that failure. An exact known replacement with reordered existing keys reproduced another mismatch. The widening source/tests and all failed logs are preserved; it was never built into an APK or measured.

Use the existing authoritative subtree reader for structural pointer parents instead. Walk only touched paths covered by a complete known value; compare the relevant child position at each ancestor, then full positions/order only for an exact object target. Record parents needing reload independently from target collapse, so a covering known target cannot bypass the read. Keep walking to identify nested changes. Before sharing the loaded result, mark every changed loaded pointer parent's positions as a replacement, preserving metadata on prior snapshots. Existing narrow scalar splices remain read-free. Canonical key order comes from SQL, including escaped keys and JavaScript integer-key enumeration.

This adds a bounded subtree READ on structural metadata/order changes. It is an explicit correctness cost, not a work-removal or performance-gain claim. There is no new retained metadata/cache/root lease, public API, schema, write SQL, FIFO or post-commit notification change. Arrays/entities retain existing atomic handling. Unknown SQL remains on its existing fallback. This repairs complete-known-write metadata and ordering; it does not claim arbitrary external SQL metadata is repaired.

Independent source review found no blocker in this active-owner repair. Inactive adoption retains a separate pre-existing input-enumeration limitation for a reordered complete known object; its metadata-addition case passes baseline. This candidate does not change that synchronous adoption path or claim universal cached ordering. The extra structural-read/order-check cost remains subject to device gates.
