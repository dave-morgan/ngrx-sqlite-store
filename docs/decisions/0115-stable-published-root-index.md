# ADR0115: reuse the private publication index for stable cached roots

Status: Rejected16af, reverted after full acceptance; all evidence preserved.

PathCache.publish currently creates and fills a new Map of every non-query cached root on every publication, then compares membership with the previous Map and updates the view. The existing private Map can instead retain membership and update changed values when the cached root set is unchanged. On membership/ownership change, rebuild the disjoint view and replace the Map exactly as before. Generation publication and eviction timing remain unchanged. No added cache, lease, schema, SQL, Store API or FIFO change.

Regression instruments private index replacement while asserting one generation, updated emitted data and an unchanged previous view: one discarded Map per stable publication must become zero. Existing ownership/ancestor absorption/LRU/query/error/recovery tests remain required. The Map is never exposed and is fully updated before generation callbacks, preserving reentrant subscriber visibility.

The larger returned-root reuse proposal is deferred: proving complete scalar shape and handling multiple commits, mutation/accessors and journal lifetime adds validation/lifecycle complexity. It must not implicitly load roots, absorb selector leases or retain unselected state.16af does not implement that proposal.

After red/green and all required checks: mandatory50kguard vs15aa, then reversedA1/B1/B2/A2 freshcoldboots+60settle/200emissions each at1k/10k/50k versus retained16r. Preserve actual installed APK/session/boot/seed/finite emission-native-overhead-raw channels and all adverse pairs. No profiler/heap snapshot/floor change. Work removed is small; do not claim latency benefit without repeatable evidence. Full fresh matched list/shapes acceptance is required if retention is warranted; list0FAIL/no mean regression guard stays open until verified.
