# ADR 0126: Native handle replacement during speculative reopen

Status: gated-open candidate provisional; isolated setup and diagnostics verified; first full acceptance16aq4 active.

Installed `@capacitor-community/sqlite` native `CapacitorSQLite.open` calls `Database.open()` on the registered wrapper. `Database.open()` unconditionally assigns `SQLiteDatabase.openOrCreateDatabase(...)` to `_db`; it has no early already-open guard. The consistency sweep closes the wrapper's current `_db`, not a previously overwritten object. Current driver startup queues speculative native open immediately after create. On WebView reload, duplicate create can fail while that open has already replaced a surviving live `_db`, before the later sweep/recreate/open path.

The existing driver mock treated open as an idempotent boolean assignment and could not represent an overwritten underlying connection. An offline regression using the actual driver plus a model of the installed Java ownership behavior found one still-live, unowned underlying handle after reload recovery. The new assertion failed; the other 25 driver tests passed. This is a source-based ownership model, not a physical native leak measurement, SQL execution or proof of the 16ap stall's cause. The installed Java SHA256 is retained in `.tmp/16aq-native-source-proof.json`; the proposed regression in `.tmp/16aq-reopen-regression-candidate.spec.ts`, original tests in `.tmp/16aq-reopen-driver-tests-baseline.ts` and RED log in `.tmp/16aq-reopen-red.log`.

Original test bytes were restored after capturing RED. No production code, APK, native plugin, schema, persistence/notification order or performance floor changed. Source16ap remains provisional. A future repair must prevent open against an existing native wrapper before closing it, while preserving recovery/error/readonly/web/iOS semantics. Waiting for create success before queuing open is a possible design; it would invalidate ADR0073's before-create-ack optimization and may add startup latency. Do not present it as a free optimization or weaken the old tests silently. It requires a new candidate, regression updates, all checks, mandatory 50k guard versus15aa, reversed APK measurement and fresh matched full list/shapes acceptance. No device run is authorized by this evidence alone while availability/storage remains unresolved.

Duplicate connection/lock/leaked SQLCipher warnings in the incomplete16ap logs are consistent with this ownership hazard. They do not establish causality, explain code13 disk-full, prove a race with unfinished seeding, or show that 16ap's registry revision introduced it; the same startup code exists in retained16r. Keep those uncertainties separate. No raw samples are discarded or merged and no acceptance verdict changes.


Offline candidate 16aq: native open is chained to successful creation on both initial and recovery paths. A failed duplicate create therefore sends no speculative open or catalog read to the surviving wrapper. Once creation succeeds, open and catalog remain ordered sends without waiting for open acknowledgement; the delayed-open-ack catalog test still passes. The recovery sweep/create remain queued in native order and the existing registry-registration test remains covered. No new native query, schema, SQL statement, cache, queue bypass or plugin fork was introduced.

The old before-create-ack assertion was explicitly replaced by a held-create-ack assertion requiring no native open while create is unresolved; the old assertion is preserved in `.tmp/16aq-source-baseline`. Reload expected call sequences remove the speculative open, and unexpected create failure now explicitly requires no open. New ownership assertion plus ordering changes fail against the original driver (4 failures/22 passes; `.tmp/16aq-gated-open-red.log`) and pass with the candidate (26 driver tests). Full candidate validation passes 433 library/29 tools/1 harness/30 E2E/library build (`.tmp/16aq-offline.stdout.log`, sentinel16AQ_OFFLINE_DONE). These are host/mock/web checks; E2E does not establish Android native behavior.

Candidate driver/tests are archived in `.tmp/16aq-source`; original live driver/tests were restored byte-for-byte afterward, and the restored library build passes (`.tmp/16aq-restored-build.log`). Candidate validation ran atop provisional16ap core/selection; those exact context files are archived alongside it. There is no candidate APK and no native/device measurement. Before any future build, explicitly choose the APK comparison baseline and record all included provisional changes. No retention or native-startup-fix claim is valid yet. Source hashes/check counts and limitations are durable in `../benchmarks/android-gated-open-offline-16aq-2026-10-29.json`.

Tradeoff remains open: waiting for create acknowledgement loses ADR0073's send gap saving. Startup regression versus15aa must be measured, not excused by the ownership test. No old acceptance is rerun unchanged, no floors change, and no incomplete16ap row is merged into future acceptance.
