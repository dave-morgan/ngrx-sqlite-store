# ADR0135: Attribute workflow onState reset wall before changing its implementation

Status: Diagnostic proposed16bh; app/library unchanged.

Workflow reset intentionally measures the classic-compatible onState bridge. Both implementations create fresh form/validation objects inside the timed reducer; this reset input is not prebuilt outside t0. SQLite onState materializes `workflow` with tx.get(), then writes the returned root. The page leases property roots rather than a complete workflow owner, and every transaction has a fresh local cache. Existing owner lookup does not assemble a complete parent from children; unselected error/membership cannot be invented from defaults. Do not replace this handler with a cheaper on/tx.set scenario or add a whole-root cache to avoid measuring the contract.

Historical16j3 observed a whole-workflow query and reset commit per iteration; current wall and payload still require measurement. The actual full-workload prelude is30edits each at depths1/4/10,15load cycles,30step changes, then10reset samples. Events and drafts are still empty at reset; do not infer a large entity payload from general capability alone.

New16bh uses unchanged16aw APK after scoped5556 cold boot+60s settling,50background todos, identical untimed prelude, one untimed setup reset and30diagnostic resets. Capture an existing Store closure binding using a setup-only function breakpoint/name/type predicates; remove breakpoint, resume and disable Debugger before timing. Wrap existing dispatch/enqueue, transaction callback entry, workflow NodeStore.read/diffWrite, selection.refresh and native query/executeSet; return original Promises. Record paths, query signatures/returned-row/source counts, changed-row counts and source/boot/session/APK identity, without state/object graphs. Preserve raw emit/DOM and nested spans; restore original descriptors/native/temporary Store reference before persisted name and table-count proof. Error partials checkpoint; fail-stop/no retry/overwrite.

Queue attribution matters: the dirty action waits for selection emission, which precedes its scanned/pipeline tail. The reset can include predecessor waiting; bracket enqueue and transaction callback entry separately. The hook's DOM wait may see old Ada text before a dirty paint, so it is not independent paint proof. Nested wall is not additive CPU/SQLCPU, a floor, full acceptance, or exact engine CPU. No extra CPU/heap/PSS/GC capture or production change.

Only an actual located cost can justify a later candidate. Equal-encoded inline replacements may cause four redundant physical row updates, but identity-replacement hints and getters/encoding semantics require correctness proof. Parent materialization reuse would require a complete current read plan handling unknown membership/unselected branches and transaction invalidation; cached fragments/defaults alone are insufficient. Any app change requires TDD/allchecks/mandatory50kguard/reversed/fullfreshmatchedacceptance and all adverse mean/heap guards. Both goals remain open.
